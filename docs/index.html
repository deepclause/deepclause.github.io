DeepClause docs

DeepClause turns specs and SOPs into executable DML harnesses. The logic that must hold is code; the model drafts and explains. Every change, run, and artifact is reviewable.

Get started with pi DML reference GitHub

Two main things

There are two ways to use DeepClause: SDD with SpecKit for software changes, and SOP2Agent for operational procedures and policies. Both run on the same DML runtime inside pi.

SDD · SpecKit for pi

Spec-driven changes in the session

Specs describe behaviour. A change is a reviewed proposal with delta specs and an executable task plan. Parsing, validation, merging and coverage are deterministic DML.

  • 0-token validation with /dc-check
  • Snapshot, resume, and abort on /dc-apply
  • Specs under specs/ are the source of truth
Read the SpecKit guide →
SOP2Agent · Handbook → DML

Turn SOPs into auditable agents

A long handbook becomes one auditable DML policy per workflow: deterministic rules for money, thresholds and deadlines, scoped LLM steps for reading and drafting, and verified post-conditions.

  • Forbidden actions have no tool
  • Deterministic amounts, thresholds, deadlines
  • Verified PASS/FAIL against post-conditions
Read the handbook guide →

Both run on the same DML runtime in pi: one model, one session, one audit trail. See the DML reference for the language.

Quick start

pi install git:github.com/deepclause/deepclause-pi
  1. /dc initializes .pi/deepclause in the workspace.
  2. For a software change: /dc-plan "add SSO" --change=sso, then /dc-check, /dc-apply, /dc-archive.
  3. For an SOP: ask pi to turn the handbook into DML, then run /dc-run skills/<policy>.dml.
